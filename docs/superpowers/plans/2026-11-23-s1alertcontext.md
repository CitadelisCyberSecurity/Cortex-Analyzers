# S1AlertContext Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-extended-cc:subagent-driven-development (recommended) or superpowers-extended-cc:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Cortex analyzer that takes a SentinelOne UAM alert ID and returns a fixed-shape context report (alert, assets, indicators, observables, process, Purple AI, related alerts, raw data) for n8n and IRIS.

**Architecture:** Scaffolded from `templates/analyzer` and modeled on `analyzers/S1ThreatContext/s1threatcontext.py`, reusing its `_request`, `_cut` and `_clean` helpers, redaction and `report()` override. It POSTs a single hard-coded GraphQL query document, with the alert ID in `variables`.

**Tech Stack:** Python 3, cortexutils, requests; pytest and responses for tests.

**Spec:** `docs/superpowers/specs/2026-11-23-s1alertcontext-design.md`. The field mappings, caps, taxonomies and report shape are defined there and not repeated here.

## Global Constraints

- Namespace `S1AlertContext`. Taxonomy predicates exactly as in the spec table: `Found, Confidence, Severity, Product, Status, Verdict, PurpleAI, Indicators`. Only `Found` (`safe` when not found) and `Confidence` (`malicious`/`suspicious`) use a level other than `info`.
- Report keys always present: `query_type, found, alert, assets, indicators, observables, process, purple_ai, related_alerts, raw_data, truncated`.
- Caps: 500 per string, 1000 for `command_line`, 2000 for the Purple AI result, 4000 for `raw_data`; at most 50 indicators, 100 observables, 20 assets, 20 related alerts.
- One HTTP call per job: `POST {url}/web/api/v2.1/unifiedalerts/graphql`, body `{"query": QUERY, "variables": {"id": <id>}}`. `QUERY` is a module constant that starts with `query ` and never contains `mutation`.
- Auth header `Authorization: ApiToken <api_token>`. Call `super().__init__(secret_phrases=("key", "password", "secret", "token"))`. The URL must be https. The token is redacted from every error.
- The alert ID must match `^[A-Za-z0-9-]{1,64}$` after stripping whitespace.
- Synthetic fixtures only (`example.test`, RFC 5737 IPs). Never real tenant data.
- `dockerImage`: `ghcr.io/citadeliscybersecurity/s1alertcontext:devel`.

**User decisions (already made):**
- Approach A: UAM alert context only. SDL raw telemetry is deferred to v2.
- A read-only POST exception to the GET-only rule, with the three guardrails in the spec.
- `PurpleAI` taxonomy is level `info` only. `Severity` is level `info` only.
- Caps as listed. Return `external_id` and `storyline_id`, no `threat_id`.

## Review Focus

1. Alert exists but `aiInvestigations` errors (no Purple AI licence): the job succeeds with `purple_ai: {}`. Test: Task 2, `test_purple_ai_error_is_ignored`.
2. HTTP 200 with `errors` and `data: null`, and the error isn't "not found": the job fails rather than reporting `Found=False`. Test: Task 2, `test_graphql_error_fails_without_token`.
3. Alert ID containing GraphQL syntax (`"`, `}`, spaces): rejected before any request. Test: Task 2, `test_bad_alert_id_rejected`.
4. Huge `rawData` (nested JSON, 50 KB): cut to 4000 characters with `truncated: true`. Test: Task 2, `test_caps_and_truncation`.
5. Purple AI status not COMPLETED (e.g. IN_PROGRESS): no `PurpleAI` taxonomy, but the `purple_ai` block is still in the report. Test: Task 2, `test_purple_ai_in_progress_has_no_taxonomy`.
